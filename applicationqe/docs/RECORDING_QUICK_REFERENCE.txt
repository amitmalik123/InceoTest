RECORDING-BASED TEST GENERATION - QUICK REFERENCE
================================================

OVERVIEW
--------
Record user interactions → AI generates framework-compliant BDD tests
Intelligently reuses existing pages/locators/steps via RAG

SETUP (ONE-TIME)
----------------
1. Install Playwright:
   pip install playwright
   playwright install

2. Index framework for RAG:
   python scripts/index_framework.py

3. Configure AI in .env:
   AI_PROVIDER=azure
   AZURE_OPENAI_ENDPOINT=https://...
   AZURE_OPENAI_KEY=...

---------------

HOW RAG REUSE WORKS
-------------------
For each recorded action:
  1. Extract selector (e.g., "input[placeholder='Search']")
  2. Query ChromaDB for similar locators
  3. If match found (>75% confidence) → REUSE existing
  4. If no match → CREATE new page/locator
  5. Generate only missing step definitions

Example:
  Recorded: page.locator("input[placeholder='Search accounts']").fill("12345")
  RAG Match: ✓ AccountListPage.search_input
  Result: → REUSE (no new code generated)


WHAT GETS GENERATED
-------------------
✓ .feature file (BDD scenarios)
✓ *_steps.py (only NEW step definitions)
✓ *_page.py (only NEW pages/locators)
✓ test_*.py (test runner)
✓ _recording_metadata.json (analysis details)

REUSED (not regenerated):
  - Existing page classes
  - Existing locators
  - Existing step definitions


PROGRAMMATIC API
----------------
from ai.generator import AITestGenerator

gen = AITestGenerator(use_rag=True)

# Generate from recording
files = gen.generate_from_recording(
    recording_file="temp_recording.py",
    feature_name="Add Wire Transfer",
    recording_type="codegen",
    output_dir="./ai/generated"
)


TROUBLESHOOTING
---------------

Problem: RAG not finding existing components
Solution: Re-index framework
  python scripts/index_framework.py

Problem: Playwright not found
Solution: Install Playwright
  pip install playwright
  playwright install

Problem: Recording has too many actions
Solution: Edit temp_recording.py manually before generation

Problem: Generated selectors too brittle
Solution: Use data-testid in app, or edit generated page objects

Problem: AI provider not configured
Solution: Check .env has AZURE_OPENAI_* or OPENAI_API_KEY


BEST PRACTICES
--------------
✓ Record clean, focused flows (one feature per recording)
✓ Keep RAG index updated (re-run index_framework.py after adding pages)
✓ Review generated code before installing
✓ Use descriptive feature names
✓ Edit recordings to remove debug/retry actions
✓ Combine with natural language generation for complex logic

BENEFITS vs. NATURAL LANGUAGE
------------------------------
Recording:
  + 100% accurate selectors (real DOM)
  + Fast (record in minutes)
  + Non-technical friendly
  + Visual workflow
  + Best for UI-heavy flows

Natural Language:
  + Flexible requirements
  + Good for validation/logic tests
  + Can describe complex scenarios
  + Best for API/edge cases

→ Use BOTH! Recording for UI, natural language for logic.
