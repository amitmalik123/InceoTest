📖 WHAT IS AUTO-HEALING?
-----------------------
Automatically repairs broken test selectors when UI changes using intelligent
fallback strategies. Tests self-heal instead of failing.

===================================================================================
🏗️ HEALING PROCESS FLOW
===================================================================================

1. Try original selector
   └─ SUCCESS? → Return locator
   └─ FAILURE? → Continue

2. Check stored alternatives
   └─ FOUND & WORKS? → Return locator
   └─ NOT FOUND/FAILED? → Continue

3. Try healing strategies (in order):
   a) TestIdStrategy
   b) LabelStrategy
   c) PlaceholderStrategy
   d) RoleStrategy
   e) TextContentStrategy
   f) SimilarElementStrategy
   └─ SUCCESS? → Store alternative & return locator
   └─ ALL FAILED? → Return None (test fails)

    healing_page = AutoHealingPage(page)

    healing_page.click("#pay-now", heal=False)         # Critical - no healing

# Pattern 3: Monitoring
def test_with_monitoring(page):
    healing_page = AutoHealingPage(page)
    healing_page.reset_healing_stats()
    # ... test actions ...
    stats = healing_page.get_healing_stats()
    if stats['total_heals'] > 3:
        pytest.warning(f"⚠️ {stats['total_heals']} selectors healed")

# Pattern 4: Parallel Execution

===================================================================================
✅ BEST PRACTICES - DO
===================================================================================

✅ Use stable selectors first
   page.get_by_test_id("login-button")

✅ Monitor healing activity
   stats = healing_page.get_healing_stats()
   if stats['total_heals'] > 0:
       print(f"⚠️ {stats['total_heals']} selectors healed")

✅ Disable healing for critical actions
   healing_page.click("#delete-account", heal=False)

✅ Review and update selectors periodically
   # Check locator_storage.json
   # Update tests with successful alternatives

✅ Alert on high healing activity
   if stats['success_rate'] < 0.5:
       pytest.fail("Too many healing failures")

===================================================================================
❌ BEST PRACTICES - DON'T
===================================================================================

❌ Don't rely only on healing
   # Bad: expecting healing to fix poor selectors
   page.locator("div > div > button:nth-child(3)")

❌ Don't ignore healing failures
   # Monitor stats and investigate failures

❌ Don't use healing for critical flows
   # Bad: healing on payment buttons
   healing_page.click("#pay-now", heal=True)
   # Good:
   healing_page.click("#pay-now", heal=False)

❌ Don't use fragile selectors
   # Bad: nth-child, complex XPath
   # Good: data-testid, labels, placeholders

===================================================================================
🐛 TROUBLESHOOTING
===================================================================================

Issue: Healing not working
Solution: Check if healing is enabled
    healing_page = AutoHealingPage(page, enable_healing=True)

Issue: Wrong element found
Solution: Use more specific selectors or disable healing
    healing_page.click("button.submit:has-text('Login')", heal=True)

Issue: Slow tests
Solution: Reduce timeouts or update selectors
    healing_page.find_element("#btn", timeout=2000)

Issue: Storage file getting large
Solution: Clear old entries
    engine.clear_storage()
